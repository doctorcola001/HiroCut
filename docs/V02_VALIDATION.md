# v0.2.2 开发验证

日期：2026-11-09。版本 `0.2.2`，versionCode `9`。

## 本轮功能

- 侧栏文件名下方显示容器 MIME、视频编码/MIME、分辨率、码率、帧率、音频编码、采样率、声道数和文件大小。
- 检测到已保存来源时，启动弹窗允许继续上次项目或清除来源/草稿开始新项目。
- 轨道卡片和时间线按显示顺序循环使用五种强调色，选中状态仍有边框和浅色填充。
- 增加 `Hybrid` 兼容导出模式。它不要求快速模式的起始 IDR 和关键帧范围，使用准确边界的编码路径。
- 修正快速模式的时间轴检查：源文件第一个同步帧不必位于 `0us`。快速模式现在根据每个实际选区寻找 In 之后的 IDR；`3855us` 只表示源文件开头有时间偏移，不再单独否决一个从中间开始的选区。

## 重要边界

用户提出的“只在拼接处几帧重新编码”属于真正的 smart-render，需要对每段前后参考帧、解码器状态、音频连续性、MP4时间戳和多段封装做更深的媒体验证。v0.2 的 `Hybrid` 曾是重新编码兜底；v0.2.2 已由 `Smart` 替代：IDR安全片段逐段流复制，边界不安全片段逐段重编码，再顺序封装。它仍不是任意帧级别的局部重编码，但不会把所有片段统一重编码。

## v0.2.2 Smart

Smart 不再把所有片段统一送入重新编码：规划器为每段标记 `smartCopy`。边界可由 IDR 安全复制的段使用 Fast 子任务；其他段使用 Precise 子任务；各临时 MP4 的音视频样本随后按片段时长偏移由 MediaMuxer 顺序写入最终文件。最终统一检查轨道、旋转、时长、音频格式和音画同步。

这仍不是任意非关键帧只重编码前后几帧的完整 GOP 级 smart-render；对于不安全边界，当前粒度是“整段重编码”。但安全的其他片段不会被重编码，保留流复制节省时间的意义。
